Secret redaction src/security.ts
src/__tests__/security.test.ts		 Added redactSecretText() for AWS access keys, GitHub tokens, Slack tokens, private keys, and OpenAI-style sk- tokens. Common accidental paste patterns are removed before memory and session persistence while preserving the rest of the message for audit/debugging.

Implementation Notes

  • mechanicallyCompact() keeps the recent tail intact when possible, but truncates tail tool results if that is the only way to avoid an oversized compacted context.
  • Memory truncation uses 20k chars per user/assistant field and 50 displayed tool calls, with 1k chars per tool-call line.
  • Session truncation uses 50k chars per persisted text field, after redaction, before encryption.
  • The changes are local to persistence/compaction helpers and tests; no agent routing, provider routing, Discord, cron, or code-agent execution behavior was rewritten.

Manual Local Testing Steps

  1. Start SkimpyClaw locally with your usual command.
  2. Send a normal chat message and confirm the response still returns.
  3. Send a message containing a fake token-shaped value such as a dynamically generated ghp_ token. Confirm future memory/session views show [REDACTED_SECRET], not the token.
  4. Run a tool-heavy prompt that produces long output. Confirm the agent continues after compaction and memory files do not grow with full huge responses.
  5. Use the dashboard memory/session views to confirm content remains readable, capped, and encrypted session history still loads.
